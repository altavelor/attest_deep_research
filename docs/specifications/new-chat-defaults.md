# Спецификация: настройки по умолчанию для нового чата

## Статус и цель

**Статус:** draft.

Пользователь должен управлять стартовой конфигурацией каждого нового чата из одного раздела настроек. Сейчас новый чат неявно всегда использует активные модель и индекс, источник `Index`, режим `Instant`, а переключатель контекста активного файла находится отдельно в Retrieval. Новый раздел делает эти значения явными, не меняя настройки уже созданных и сохранённых чатов.

## Решения и допущения

- Раздел называется **New chat defaults** и располагается в корне настроек Ixplorer, после профилей моделей и индексов, до Retrieval.
- Настройки применяются только при создании нового чата: при первом открытии пустого чата и по действию **New chat**. Сохранённые чаты сохраняют собственные настройки и не изменяются после смены глобальных defaults.
- Текущие стартовые значения сохраняются как начальные значения новой категории:
  - Source: `Index`;
  - Index: текущий `activeIndexProfileId`;
  - Mode: `Instant`;
  - Model: текущий `activeChatModelProfileId`;
  - Include active file as context: `true`.
- В v1 значение источника не корректируется автоматически при недоступном индексе или web-провайдере. Интерфейс чата показывает существующую причину недоступности отправки; пользователь может сменить источник или исправить конфигурацию.
- «Default» означает только настройку старта нового чата. В таблицах model/index profiles этот статус и действие больше не отображаются.

## Пользовательский интерфейс

Раздел содержит пять настроек, сохраняемых сразу после изменения.

| Поле                           | Контрол           | Допустимые значения                   | Поведение                                                                                                                 |
| ------------------------------ | ----------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Default source                 | Выпадающий список | `None`, `Index`, `Web`, `Index + Web` | Определяет стартовый `searchMode` нового чата.                                                                            |
| Default index                  | Выпадающий список | все доступные index profiles          | Определяет стартовый `indexProfileId`; используется, когда источник содержит Index.                                       |
| Default mode                   | Выпадающий список | `Instant`, `Thinking`                 | Определяет стартовый research mode. `Thinking` доступен только при выбранной модели с Agent capability.                   |
| Default model                  | Выпадающий список | все несuspended chat model profiles   | Определяет стартовый `chatModelProfileId`.                                                                                |
| Include active file as context | Toggle            | on/off                                | При включении новый чат автоматически прикладывает текущий поддерживаемый активный файл согласно существующему поведению. |

Правила доступности:

- Если нет подходящих профилей, выпадающий список пуст и показывает понятное состояние «No available …». Нельзя записать несуществующий ID через UI.
- Suspended profile не показывается как доступный выбор. Если сохранённое значение стало suspended, удалено или невалидно, при нормализации оно заменяется первым доступным профилем либо пустой строкой, если подходящих профилей нет.
- Для Default index в список входят только несuspended профили; неиндексированный профиль остаётся выбираемым, но новый чат с источником Index будет использовать существующее предупреждение/валидацию до построения индекса.
- Если выбранная модель не поддерживает Thinking, контрол режима показывает `Thinking` disabled с объяснением. При загрузке устаревшего/невалидного значения `thinking` для такой модели default нормализуется в `instant`.
- Default index остаётся видимым и сохраняемым при `None` или `Web`, чтобы выбор восстанавливался, когда пользователь позднее выберет источник с Index.

Перемещение переключателя:

- **Include active file as context** удаляется из `Retrieval → Local context` и рендерится только в New chat defaults.
- Остальные настройки Retrieval и фактическая логика добавления активного файла не меняются.

## Модель данных и миграция

В persisted `IxplorerSettings` добавляется группа `newChatDefaults`:

```ts
interface NewChatDefaults {
  searchMode: "none" | "indexOnly" | "webOnly" | "indexAndWeb";
  indexProfileId: string;
  researchMode: "instant" | "thinking";
  chatModelProfileId: string;
  includeActiveFileContext: boolean;
}
```

`activeChatModelProfileId` и `activeIndexProfileId` удаляются из публичной модели настроек и persistence-схемы; их единственная прежняя функция была определением начального состояния чата. Любые места, которые сейчас читают эти поля, должны читать соответствующее поле `newChatDefaults`.

При чтении сохранённых настроек без `newChatDefaults` выполняется без потери пользовательских данных миграция в памяти и при следующем сохранении записывается новая форма:

```ts
newChatDefaults = {
  searchMode: "indexOnly",
  indexProfileId: saved.activeIndexProfileId,
  researchMode: "instant",
  chatModelProfileId: saved.activeChatModelProfileId,
  includeActiveFileContext: saved.includeActiveFileContext,
};
```

Если старый ID отсутствует или невалиден, применяется нормализация, описанная выше. Для совершенно новых/повреждённых настроек используются значения из раздела «Решения и допущения» и пустые ID до добавления профилей. После миграции прежние ключи `activeChatModelProfileId`, `activeIndexProfileId` и верхнеуровневый `includeActiveFileContext` не сохраняются обратно.

`SavedChatSettings` не меняется: он уже хранит model, index, source и mode на уровне чата. Контекст активного файла остаётся глобальным default-поведением и не становится частью сохранённого чата.

## Поведение нового чата

`createDefaultChatSettings` должен строить `SavedChatSettings` из `newChatDefaults`, с теми же проверками доступности профилей, что и при загрузке сохранённого чата. Значения mapping:

| UI source   | `searchMode`  |
| ----------- | ------------- |
| None        | `none`        |
| Index       | `indexOnly`   |
| Web         | `webOnly`     |
| Index + Web | `indexAndWeb` |

Создание нового чата не должно менять глобальные defaults, когда пользователь затем переключает модель, источник, индекс или режим в composer. Эти изменения относятся только к текущему чату и сохраняются с ним по существующим правилам.

## Удаление default-функций из таблиц

- В таблице **Chat model profiles** удалить бейдж `Default` и действие со звездой `Set as default model` / `Default model`.
- В таблице **Index profiles** удалить бейдж `Default` и действие со звездой `Set as default index` / `Default index`.
- Удалить специфичные для них CSS-классы, тесты и статус-ветки, если после удаления они не используются.
- Статусы профилей (suspended, error, stale, indexing и т. п.), редактирование, удаление, построение и capability actions сохраняются без изменений.

## Архитектура

| Область                          | Изменение                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `src/adapters/settings/`         | Тип группы defaults, значения по умолчанию, безопасная миграция/нормализация и экспорт helper-ов.             |
| `src/apps/obsidian/ui/settings/` | Отдельный `NewChatDefaultsSection`; удаление active-file toggle из Retrieval и default-UI из таблиц профилей. |
| `src/apps/obsidian/main.ts`      | Передавать new-chat defaults в сервисы представления вместо active ID.                                        |
| `src/apps/obsidian/ui/chat/`     | Создавать новый чат из defaults; сохранить изоляцию текущего/сохранённого чата.                               |
| `tests/unit/`                    | Проверки миграции, нормализации, создания нового чата и UI-контрактов.                                        |

Изменение должно соблюсти направления зависимостей `apps → adapters → application → core`. Новый UI не должен читать persistence напрямую: он получает и сохраняет `IxplorerSettings` через существующий plugin API.

## Тестирование и критерии приёмки

- Новый раздел содержит все пять полей и корректные четыре варианта источника.
- Чистая установка получает `Index`, `Instant`, включённый active-file context и пустые model/index ID до настройки профилей.
- Существующая установка после обновления получает те же стартовые модель, индекс, `Index`, `Instant` и active-file toggle, что были до обновления.
- Новые чаты используют каждое значение new-chat defaults; изменение значения в composer не меняет defaults.
- Сохранённый чат открывается со своими model/index/source/mode, даже если глобальные defaults позднее изменены.
- Невалидные, удалённые и suspended IDs не приводят к ошибке и нормализуются к доступному профилю или пустому значению.
- Thinking не может быть default для модели без Agent capability; невалидное сохранённое сочетание деградирует до Instant.
- В таблицах моделей и индексов отсутствуют default badge, star action и возможность назначить объект default; все остальные действия и статусы остаются.
- Active-file toggle отображается ровно один раз — в New chat defaults — и его текущее поведение не регрессирует.
- `npm run check` проходит.

## Границы

- Всегда: сохранять обратную совместимость persisted settings и saved chats, валидировать сохранённые ID, обрабатывать пустые списки профилей и добавлять регрессионные тесты.
- Спросить сначала: менять поведение активного файла для уже открытого/сохранённого чата, добавлять новые режимы источников, зависимости или изменять формат SavedChatSettings.
- Никогда: молча заменять пользовательский выбор другим доступным профилем во время активного чата, удалять сохранённые чаты или изменять их настройки при миграции глобальных defaults.

## Открытые вопросы

Нет. Спецификация трактует фразу «текущие настройки по умолчанию» как фактическое нынешнее поведение нового чата: `Index`, `Instant`, active model/index и включённый active-file context.
