# Спецификация: debug-вкладка Index search

## Статус

Черновик спецификации с подтверждёнными продуктовыми решениями. Реализация не входит в этот документ.

## Цель

Сделать `Index search` диагностическим инструментом, а не пользовательским интерфейсом управления индексированием.

Пользователь с включённым Debug mode может выбрать готовый индекс, выполнить запрос и просмотреть результаты. Пользователь без Debug mode не видит ни вкладку, ни её содержимое. Управление индексированием остаётся в настройках плагина и не дублируется на вкладке поиска.

## Контекст и текущая реализация

- Вкладка создаётся в `src/apps/obsidian/ui/chat/ChatHeader.ts` и переключается через `IxplorerChatView`.
- Её содержимое формируют `IndexSearchController` и `IndexSearchPanel`.
- Внутри вкладки сейчас рендерится `IndexControl`, предоставляющий Start, Update, Pause, Continue и Rebuild.
- Панель также содержит фильтры `Top K`, `Min score` и `Ext`.
- Индекс зависит от embedding model profile. Нормализация настроек приостанавливает индекс, если его embedding-профиль не задан или приостановлен.

## Функциональные требования

### Видимость вкладки

1. При `settings.debugMode === false` Chat view отображает только чат: переключатель вкладок (`tablist`) и обе tab-кнопки не создаются в DOM.
2. При `settings.debugMode === true` в заголовке чата появляется переключатель вкладок с `Chat` и `Index search`.
3. Вне debug-режима `Index search` не доступна через переключение панели и её содержимое не создаётся в DOM.
4. Если Debug mode выключен, пока `Index search` активна, view безопасно возвращается на `Chat`; не остаётся пустой активной панели, скрытого поля ввода или подписок, специфичных для этой вкладки.
5. Включение или выключение Debug mode начинает действовать после следующей перерисовки view (в частности, после повторного открытия view или обновления интерфейса, принятого существующим жизненным циклом настроек). Мгновенная перерисовка уже открытого view не требуется, если отдельно не будет согласована.

### Состав панели

В debug-режиме панель содержит только:

1. Выбор индексного профиля. В селекторе доступны только пригодные для поиска, уже проиндексированные профили; непригодные профили остаются недоступными в соответствии с текущим поведением.
2. Существующие параметры поискового запроса: `Top K`, `Min score`, `Ext`.
3. Поле текстового запроса.
4. Кнопку отправки запроса и отправку по Enter; Shift+Enter добавляет перевод строки.
5. Область состояния и результатов: ожидание, ошибка, пустой результат и список найденных фрагментов с переходом к источнику.
6. Warning о недоступном embedder или semantic degradation RAG-поиска, когда он применим.

Из панели полностью удаляются:

- статус, прогресс и все кнопки `IndexControl`;
- действия Start/Update/Pause/Continue/Rebuild;
- подписка на состояние индексирования, контекстные методы и типы, нужные только для `IndexControl`;

Фильтры `Top K`, `Min score`, `Ext` остаются без изменения: это параметры отправки поискового запроса, а не управление процессом индексирования.

Удаление относится только к вкладке `Index search`: существующее управление индексированием в Settings и его сервисы не меняются.

### Запрос к индексу

1. Пустой запрос не отправляется.
2. Во время выполнения запроса selector, поле и кнопка недоступны; отображается `Searching index...`.
3. После завершения управления снова доступны, а результаты либо понятная ошибка показаны в панели.
4. Поиск сохраняет текущие пользовательские параметры: `Top K` передаётся как `limit`, `Min score` — как `minScore`, `Ext` — как ограничение расширений файлов. Их валидация и значения по умолчанию не меняются.
5. Ошибки запроса по-прежнему преобразуются в безопасное пользовательское сообщение; технические детали или секреты не выводятся.

### Warning об embedder и RAG-degradation

1. Warning визуально отличается от ошибки результата и имеет семантику предупреждения (`role=\"alert\"` или эквивалентный доступный паттерн).
2. До отправки запроса он показывается, если уже известно, что embedding-модель выбранного индекса недоступна или некорректно сконфигурирована: профиль не выбран, приостановлен либо capability-проверка уже признала его непригодным. Сообщение включает безопасную причину и действие: исправить embedding model profile в Settings.
3. Такая известная конфигурационная недоступность блокирует отправку поиска: retrieval нельзя корректно создать. Если нет пригодного профиля, selector остаётся в своём текущем disabled-состоянии, а warning объясняет, почему поиск недоступен.
4. Во время поиска `RetrievalService` может поймать ошибку semantic/embedding path и продолжить keyword-only ranking. Это не считается провалом всего запроса: результаты показываются, а над ними отображается warning о деградации с тем же смыслом, что уже применяется в Chat — `Index search degraded to keyword-only ranking` и безопасная причина semantic error.
5. Runtime-warning не блокирует текущий или последующие поиски: keyword fallback является штатным деградированным результатом. Он очищается перед следующим запросом и повторно устанавливается только по `semanticError` нового retrieval result.
6. Warning не запускает индексирование и не предлагает кнопки управления им.

## Нефункциональные требования

- Сохраняются доступные `aria-label` у selector, поля и кнопки поиска.
- Не добавляются зависимости, настройки или новые внешние запросы лишь ради отображения панели.
- Архитектурные границы сохраняются: UI получает состояние через узкий контекст; UI не создаёт embedding-клиент и не обращается к сетевым API напрямую.
- При закрытии view не остаётся подписок на index search или индексирование, созданных только для этой вкладки.

## Технический подход

1. Сделать список вкладок зависимым от `isDebugMode()` и запретить/нормализовать выбор `indexSearch` вне debug-режима.
2. Упростить `IndexSearchPanel` и `IndexSearchController`: удалить refs, API и рендеринг `IndexControl`; сохранить профиль, поисковые фильтры, запрос, отправку и результаты.
3. Добавить в контекст панели read-only признак и сообщение известной недоступности embedder выбранного профиля. Вычислять его в composition/settings-слое по данным index profile, embedding model profile и сохранённой capability-проверке, а не дублировать логику в DOM-коде.
4. Изменить контракт debug-поиска так, чтобы UI получал не только chunks, но и retrieval diagnostics (`semanticError`, при необходимости `usedFallback`); не терять их в `main.ts` при возврате результата `RetrievalService.search()`.
5. До запроса отключать submit только при известной конфигурационной недоступности; после запроса отображать warning keyword-only fallback по `semanticError` без отмены результатов.
6. Удалить неиспользуемые CSS-правила и зависимости от index-control из пути index search, не затрагивая стили/работу IndexControl в других местах.

## Затрагиваемая структура

```text
src/apps/obsidian/ui/chat/ChatHeader.ts
  → условное создание debug-вкладки
src/apps/obsidian/ui/chat/IxplorerChatView.ts
  → безопасный active panel, передача debug и embedder-status в controller
src/apps/obsidian/ui/index/IndexSearchController.ts
  → только поиск, результаты и два источника warning; без IndexControl
src/apps/obsidian/ui/index/IndexSearchPanel.ts
  → форма поиска с текущими фильтрами и доступный warning
src/apps/obsidian/ui/index/index-search.css
  → стили warning; удаление стилей index-control при отсутствии использования
src/apps/obsidian/composition/ (либо узкий settings helper)
  → единое определение известной доступности embedder для выбранного index profile
tests/unit/
  → контракт рендеринга, controller/panel и доступность embedder
```

## Стиль кода

Следуем текущей императивной Obsidian-UI модели, с typed options и ранними выходами:

```ts
if (!options.isDebugMode) {
  return;
}

containerEl.createDiv({
  cls: "ixplorer-index-search__warning",
  text: options.embedderWarning,
  attr: { role: "alert" },
});
```

- TypeScript strict; cross-module imports через aliases.
- Никаких новых комментариев, кроме кратких описаний при необходимости.
- Не помещать бизнес-логику определения профиля в рендер-функции.

## Стратегия тестирования

1. Unit/contract test для `ChatHeader`: `Index search` присутствует только при debug=true.
2. Unit test view/controller: вне debug невозможно оставить `indexSearch` активной; контент панели не рендерится.
3. Unit test `IndexSearchPanel`: отсутствуют `IndexControl` и его actions; selector, Top K, Min score, Ext, query и search button остаются.
4. Unit test controller: запрос передаёт выбранный профиль, query, limit, minScore и extension; повторная отправка во время поиска исключена.
5. Unit test preflight-warning: отсутствующий, приостановленный или ранее признанный непригодным embedder показывает доступное предупреждение и disables submit; доступный embedder не показывает warning.
6. Unit test RAG-warning: `semanticError` в retrieval result сохраняет найденные chunks и показывает keyword-only warning; warning очищается перед следующим запросом и не появляется при успешном semantic search.
7. Регрессия: результат поиска открывает исходный chunk, а не относящаяся к semantic fallback ошибка retrieval остаётся пользовательской ошибкой.
8. Полная проверка перед коммитом: `npm ci` и `npm run check`.

## Границы

- Всегда: сохранять обратную совместимость настроек, очищать подписки, тестировать изменённое поведение и выполнять `npm run check` перед публикацией.
- Спросить прежде: менять схему settings, добавлять зависимости, менять поведение индексирования или параметров поиска в Settings, добавлять runtime-probe embedder при открытии панели.
- Никогда: запускать/пауза/пересобирать индекс из `Index search`; показывать вкладку вне Debug mode; выводить API keys или сырой текст сетевых ошибок.

## Критерии готовности

- [ ] При выключенном Debug mode в DOM нет `tablist`, вкладок или панели `Index search`, а Chat остаётся работоспособным.
- [ ] При включённом Debug mode вкладка доступна и содержит selector индекса, Top K, Min score, Ext, поле запроса, кнопку поиска, warning (когда нужен) и область результатов.
- [ ] На вкладке нет кнопок или состояния управления индексированием; параметры поиска Top K/Min score/Ext сохранены.
- [ ] Уже известный неработоспособный или некорректно настроенный embedder даёт понятный доступный warning и блокирует поиск.
- [ ] Семантическая ошибка во время RAG-поиска не скрывает keyword-only результаты и отображается отдельным warning, как в Chat.
- [ ] Доступный embedder не показывает preflight-warning, а поиск использует заданные пользователем параметры фильтра.
- [ ] Ошибки самого поиска отличимы от обоих видов warning и остаются безопасными для пользователя.
- [ ] Новые и существующие тесты проходят, как и `npm run check`.

## Решения, подтверждённые пользователем

1. При выключенном Debug mode переключателя вкладок нет; отображается только Chat view.
2. При включённом Debug mode переключатель с Chat и Index search появляется.
3. Top K, Min score и Ext остаются как текущие параметры поиска.
4. Warning показывается как при известной проблеме embedder, так и при semantic degradation во время RAG-поиска по существующему Chat-контракту keyword-only fallback.
